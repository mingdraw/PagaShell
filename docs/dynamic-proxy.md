# 网关动态代理

## 使用

1. 右键 SSH 或 Page 网关，选择「动态代理」。每个网关复用一个独立标签，打开标签不会建立连接。
2. 通过 Radio Card 选择「规则」或「全局」模式，勾选 `HTTP(S)`、`SOCKS5` 并设置监听端口。`HTTP(S)` 使用一个开关和端口同时代理 HTTP 与 HTTPS，默认 `18080`；SOCKS5 默认端口 `1080`，可使用独立端口或与 HTTP(S) 共用端口。
3. 可在「启动代理」旁勾选「自动设置系统网络代理」（默认关闭），本地监听成功后才写入系统设置。未勾选时，在浏览器或应用中手动设置代理地址 `127.0.0.1` 和对应端口。
4. 点击「停止代理」先恢复本应用设置的系统代理，再释放监听和活动连接。启动中也可以停止；修改运行中的配置前需要先停止。

配置随网关自动保存，应用重启后需手动启动。端口范围为 1–65535；任一监听端口被占用则本次启动整体回滚。关闭代理标签或删除网关只清理该代理的监听、隧道和专用网关连接；正常退出应用会等待系统代理恢复并清理全部会话。

## 自动设置系统网络代理

| 平台 | 作用范围与要求 |
| --- | --- |
| macOS | 为当前 IPv4/IPv6 主网络服务设置 HTTP、HTTPS CONNECT 和 SOCKS 代理；需要时由系统弹窗请求网络配置权限。GitHub 桌面版不启用 App Sandbox，以使用 Authorization Services；升级后继续使用已有沙盒数据库和保险库文件。 |
| Windows | 通过 WinINet 修改当前用户默认 LAN/Internet 代理并刷新设置；HTTP 与 HTTPS 均指向普通 HTTP 代理端口。SOCKS 明确使用 SOCKS5 URI，Chrome/Edge 可识别；旧 WinINet 应用不一定支持此 SOCKS5 写法，建议同时开启 HTTP(S)。 |
| Linux | 支持 GNOME 的 GSettings 和 KDE Plasma 5/6 的 KConfig；GNOME 需 `gsettings` 与相应 schema，KDE 需同版本的 `kreadconfig5/6`、`kwriteconfig5/6` 及 `dbus-send`。使用当前桌面用户会话；接口缺失、不支持的桌面或配置不可写时明确报错。 |

- 只影响遵循系统代理设置的应用，不修改 hosts 或终端的代理环境变量。规则/全局选路仍由本地动态代理处理。
- 启动前检查已有手动代理、PAC、自动发现（WPAD）；Linux 还检查继承的代理环境变量。存在冲突时拒绝覆盖，本次代理启动回滚；可先停止其他代理，或取消自动设置后手动配置应用。
- 同一时间只有一个网关可以自动设置系统代理。其他网关可不勾选该选项，使用各自的手动代理端口。
- 停止、关闭标签、删除网关和正常退出均等待恢复。恢复仅修改仍属于本应用的设置，其他应用接管的配置或修改的绕过列表会保留。若部分接管后仍有设置指向本应用，保留监听并提示在系统设置中移除剩余条目后重试停止。
- 授权被取消或设置失败时回滚；恢复失败时标签显示「系统代理待恢复」，可重试停止。恢复成功前不关闭对应监听，退出操作也会取消。快照只保存在进程内；强制结束进程后需在系统设置中手动取消遗留的本地代理。

## Clash Verge 共存

关闭「自动设置系统网络代理」后，启动/停止代理按钮右侧显示「Clash 扩展脚本」按钮。点击可按当前表单中的协议、端口和规则生成脚本，在弹窗中选择或一键复制；不需要先启动代理。勾选自动设置后隐藏此按钮。

在 Clash Verge 的订阅卡片上右键，打开「编辑扩展脚本」并粘贴；已有自定义脚本时合入原来的 `main` 函数。脚本添加一个仅指向 `127.0.0.1` 的本地节点，优先选 HTTP(S)，仅启用 SOCKS5 时使用 TCP SOCKS5 节点。节点名称包含网关名称和 ID，不包含网关令牌或其他凭据。

导出跟随 PagaShell 当前选择的模式：

- 全局模式：保留 Clash 已有的具体规则，将原 `MATCH` / `FINAL` 兜底替换为最后一条 `MATCH,PagaShell-…`，使其余流量通过当前网关。此时不导出规则模式下保存的规则。
- 规则模式：把当前规则放到 Clash 原有规则前面，精确域名和后缀分别转换为 `DOMAIN`、`DOMAIN-SUFFIX`，前缀转换为锚定开头的 `DOMAIN-REGEX`，IPv4/IPv6 转换为对应 CIDR 规则。域名规则优先于可能触发 DNS 解析的 IP 规则；空规则列表只添加节点。未匹配请求继续沿用 Clash 原有分流，IP 规则所需的域名解析由 Clash 的 DNS 配置决定。

Clash 使用规则模式并开启系统代理；PagaShell 按需选择全局或规则模式，并关闭自动设置系统网络代理后启动。开启 TUN 时，应确保网关地址的路由不会回到本地节点。脚本目前需手动更新，修改 PagaShell 模式、规则或监听端口后需重新复制到 Clash。

## 协议

| 选项 | 行为 | 应用侧设置 |
| --- | --- | --- |
| HTTP(S) | 同时转发 HTTP 请求及 HTTPS CONNECT；保留 HTTP 的 `Host`、路径和请求体，HTTPS 隧道原样传输网站 TLS 和 SNI | HTTP 和 HTTPS 网站都设置为代理 `http://127.0.0.1:18080` |
| SOCKS5 | 无认证 TCP CONNECT，支持 IPv4、IPv6 和域名；不支持 BIND、UDP ASSOCIATE | SOCKS5 `127.0.0.1:1080`，建议开启通过代理解析域名 |

HTTP(S) 中的 HTTPS 使用 CONNECT 隧道，无需本地代理证书，也无需向系统安装证书。浏览器仍负责验证网站证书；应用连接本地代理本身使用普通 TCP。Page 网关到中转 Server 的加密方式继续使用已有网关配置，SSH 网关继续校验网关主机密钥。

旧配置只启用 HTTPS 时沿用原 HTTPS 端口；其他情况优先沿用原 HTTP 端口。启动或保存后，HTTP 与 HTTPS 的开关和端口同步。

例如，HTTPS 网站 `https://app.internal.example` 经 CONNECT 转发后仍保留该域名，服务端 openresty 可按原有 SNI/Host 选择网站。不要把目标 URL 改成本地 IP。

```bash
# HTTP 代理端口同时开启 HTTPS CONNECT
curl --noproxy '' --proxy http://127.0.0.1:18080 https://app.internal.example

# SOCKS5 发送原始域名给代理，允许网关解析内网域名
curl --noproxy '' --socks5-hostname 127.0.0.1:1080 https://app.internal.example
```

## 模式与规则

| 模式 | 路由 |
| --- | --- |
| 全局 | 所有请求通过当前 SSH 网关或内网 Page Client 连接目标 |
| 规则 | 命中任一规则通过网关；未命中由本机直连；空规则列表等效全部直连 |

两种模式启动时均需准备网关凭据。旧配置中的「直连」模式读取为「规则」模式，已有协议、端口和规则保留。选定网关后，目标访问失败会向应用返回错误，绝不自动回退直连。Page 目标继续受 Client 的 `allowed_targets` 限制；SSH 目标须允许 `direct-tcpip` 转发，无需目标机器有 SSH 或 22 端口。

| 匹配方式 | 配置示例 | 命中示例 |
| --- | --- | --- |
| IP / CIDR | `10.0.0.5`、`10.0.0.0/16`、`2001:db8::/32`、`::1` | 单个地址或网段内的 IPv4/IPv6 |
| 域名全匹配 | `api.example.com` | 仅该域名 |
| 域名前缀 | `api.` | `api.example.com`、`api.internal` |
| 域名后缀 | `example.com` | `example.com` 和 `a.example.com`，不含 `evilexample.com` |

域名不区分大小写，目标末尾的 DNS 根点不影响匹配。域名规则填写域名或前缀本身，不填 `http://`、端口、路径或 `*`；国际化域名可填写 Punycode。

目标是域名时先匹配域名规则。未命中且存在 IP 规则时，使用本机 DNS 结果匹配；任一地址命中则选网关，解析失败返回错误。命中网关后仍把原始域名传给网关，由网关解析。内网专用域名应配置域名规则，避免依赖本机 DNS。应用若自行解析域名再向 SOCKS5 发送 IP，代理只能按 IP 规则匹配。

## 存储和验证

数据库 schema 13 在网关记录中增加 `proxy_config_json`，从 schema 12 升级保留现有端口映射、网关和服务引用。`autoSystemProxy` 随网关保存，旧配置默认为关闭，此偏好不发送给 Rust 引擎。配置导出内容版本为 4，包含动态代理设置及规则；仍可导入 1/2/3 版文件。运行状态和系统代理快照不导出、不自动恢复。

本地测试覆盖协议开关、分块请求体、HTTP 连接复用、CONNECT 提前数据与半关闭、SOCKS5 IPv4/IPv6/域名、规则选路、失败不回退、端口绑定回滚、停止/启动竞争，以及真实 SSH 和 Go Page 中转。自动系统代理增加模拟平台测试，覆盖 GNOME/KDE 设置和恢复、静态/PAC/WPAD 冲突、其他应用接管、写入回滚、恢复重试和会话清理；macOS 原生代码通过本机构建检查。实际系统代理写入、浏览器行为和 Windows/Linux 原生运行仍需在对应环境验收。
